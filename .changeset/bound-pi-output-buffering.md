The Pi adapter's tools now keep the memory of the host process bounded. The bash tool keeps only the tail of a command's output that it displays, together with the byte and line counts of the whole output for the truncation notice, instead of holding all of the output in memory. When the result is truncated, that retained tail is written to `/tmp/pi-bash-<toolCallId>.log` in the sandbox and the notice says whether the file holds the full output or only the tail, so output beyond the retained tail is no longer saved in full. A command that produces more than 16MB of output is stopped. The `read` tool refuses to load a file that is above a size limit or that is not a regular file into the host, where it used to read whole files of any size, and the `grep` tool now selects context lines in the sandbox and bounds how much of a matching file it transfers instead of loading whole matching files. A command that produced a lot of output, a large repository file, or a match in such a file could previously exhaust the memory of the agent process that hosts the session and serves other sessions.
