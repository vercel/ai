# MCP Events (Experimental)

The MCP client supports catalog discovery and webhook subscription requests from the
[draft MCP Events extension](https://github.com/modelcontextprotocol/experimental-ext-triggers-events/blob/28ec35e905daa241f019981e2836b4a02f1c0368/docs/design-sketch-proposal.md).
These APIs are experimental and may change alongside the draft.

Event protocol methods are separate from `tools/list` and `tools/call`. Calling
`experimental_listEvents()` discovers event definitions; it does not subscribe or
automatically add tools to the model.

## Discover event types

Use the same authenticated client as your other MCP requests. The server must
advertise an `events` capability. Each call returns one catalog page:

```ts
const page = await client.experimental_listEvents();
const webhookEvents = page.events.filter(event =>
  event.delivery.includes('webhook'),
);

if (page.nextCursor != null) {
  const nextPage = await client.experimental_listEvents({
    params: { cursor: page.nextCursor },
  });
}
```

Definitions include `name`, `description`, `delivery`, `inputSchema` (subscription
arguments), `payloadSchema` (delivered event data), and optional `_meta`. The client
does not cache the catalog. Keep application caches scoped to the authenticated
account/grant. Re-fetch to pick up catalog changes; server notifications are not
handled by this client.

## Expose subscription tools to a model

Use `experimental_eventToolsFromDefinitions` to generate callable subscription
tools from selected event definitions. This is an explicit opt-in: ordinary
`client.tools()` calls continue to expose only the server's `tools/list` catalog.

```ts
import { experimental_eventToolsFromDefinitions as eventToolsFromDefinitions } from '@ai-sdk/mcp';

const page = await client.experimental_listEvents();
const eventTools = eventToolsFromDefinitions(page, {
  needsApproval: true,
  toolName: event =>
    `issues__watch_${event.name.replace(/[^a-zA-Z0-9_-]/g, '_')}`,
  subscribe: async ({ name, arguments: args }, executionOptions) => {
    // Application code, with the authenticated account/conversation bound
    // outside model-controlled arguments. Validate the event arguments here.
    return subscriptionService.subscribe({
      name,
      arguments: args,
      signal: executionOptions.abortSignal,
    });
  },
});
```

`subscriptionService` represents your application's authorized subscription
handler; it is not an AI SDK export. It can call a managed backend such as Connect,
or use `experimental_subscribeEvent()` after preparing its own durable receiver.
The helper itself never sends protocol requests or creates subscriptions during
discovery. Its `subscribe` callback runs only when the tool is executed. Return a
model-safe receipt, such as a watch ID and its actual pending/active state, without
including credentials or receiver secrets.

Pass `eventTools` to `generateText`, `streamText`, or your agent's tool discovery
layer. For the `issue.created` definition, the generated model tool can receive
`{ project_id: 'ABC' }`; its execute handler binds the event name and calls
`subscribe({ name: 'issue.created', arguments: { project_id: 'ABC' } }, options)`.

The helper:

- Includes only definitions advertising `webhook` delivery. Poll-only and
  push-only events are omitted.
- Preserves `inputSchema` at the tool root, including local `$ref` and `$defs`
  resolution. It does not add a nested `arguments` property or application-specific
  fields for instructions, users, callback URLs, or lifetimes.
- Uses `mcp_subscribe_` plus the sanitized event name by default. `toolName` can
  provide an application namespace. Names must contain 1–64 letters, digits,
  underscores or hyphens; duplicate names are rejected rather than overwritten.
- Forwards tool execution options, including the abort signal, to the subscription
  handler. `needsApproval` optionally sets the AI SDK approval requirement.
- Leaves results to the handler. `payloadSchema` describes later event deliveries,
  not the tool's subscription receipt, so it is not used as `outputSchema`.

Supply only the definitions you want to expose, fetching additional catalog pages
as needed. The helper has no shared catalog cache. When combining its results with
remote tools, reserve a namespace and check for collisions across the combined
tool set; the helper can detect collisions only within the definitions it receives.

The server's JSON Schema guides model arguments; as with automatic MCP tool
conversion, it does not install a full JSON Schema runtime validator. The callback
or subscription backend must validate the selected event and its arguments and
enforce current authorization. The helper rejects non-object inputs, but argument
fields such as `userId` or `delivery` are still untrusted event arguments, not
trusted routing or authentication configuration. Do not spread them into backend
options. Approval prompts do not replace backend authorization.

Frameworks can add their own watch policy, task instructions and conversation
bindings around this primitive. An SDK upgrade alone does not mount a framework
receiver or resume conversations when events arrive.

## Register or refresh a webhook

Prepare a durable receiver **before** subscribing. The server may send a signed
verification challenge before returning the subscription response. Generate and
store its signing secret before making the request; the response's subscription ID
is not available during that challenge.

```ts
import { experimental_generateMCPWebhookSecret as generateMCPWebhookSecret } from '@ai-sdk/mcp';

const secret = generateMCPWebhookSecret();

// Application code: persist the secret and enable verification at this URL.
await registerReceiver({ url: callbackUrl, secret });

const params = {
  name: 'issue.created',
  arguments: { project_id: 'ABC' },
  delivery: { url: callbackUrl, secret },
  ttlMs: 3_600_000,
};

const subscription = await client.experimental_subscribeEvent(params);
await saveSubscription({ params, subscription });
```

`registerReceiver` and `saveSubscription` represent your application's durable
storage/receiver implementation, not AI SDK functions. The callback must use HTTPS;
`secret` must be a `whsec_` value encoding 24–64 random bytes. The helper generates
32 random bytes using Web Crypto. Never expose the secret or callback configuration
as model-controlled subscription arguments.

The client supplies `delivery.mode: 'webhook'` on the wire automatically because
`events/subscribe` supports only webhook delivery. Unsubscribe sends only the
callback URL in `delivery`.

The application or a managed subscription service is responsible for:

- Verifying Standard Webhooks signatures and timestamps on the raw body, responding
  to verification challenges, and deduplicating accepted deliveries.
- Persisting the subscription and scheduling refreshes before the server's granted
  `refreshBefore`. Re-call `experimental_subscribeEvent()` with the same name,
  arguments, callback and latest persisted cursor.
- Handling verification, gap and terminated control envelopes at its receiver.
- Routing authenticated events into its own queue, workflow or conversation.

The AI SDK does not mount a receiver, start a renewal timer or keep a process alive.
Closing the MCP client does not unsubscribe webhook watches.

### Lifetime and replay

- Omit `ttlMs` for the server's default grant. A finite value suggests a lifetime;
  always schedule against the returned `refreshBefore`.
- `ttlMs: null` explicitly requests no expiry. The server may still grant a finite
  lifetime. `refreshBefore: null` means no expiry was granted; periodic health and
  catalog checks are still recommended by the draft.
- The draft forbids granting no expiry unless requested. If a server violates that
  rule, the client still returns the accepted grant and its ID so the application
  can inspect and explicitly unsubscribe it. Validate the grant against application
  policy; rejecting a response does not undo an already-created watch.
- `cursor` is an opaque replay position. Omitted and null cursors both mean start
  now. Missing response cursors are normalized to null; string cursors are preserved.
  Persist the watermark from both subscribe responses and verified deliveries.
- `maxAgeMs` bounds requested replay. `truncated: true` reports a possible gap;
  it is returned to the application rather than rejected as a failed subscription.
- Optional `deliveryStatus` reports delivery health and throttling information.

Subscription setup errors can be ambiguous: a server may create a watch before
the response is lost. Retain the original request tuple and secret so your durable
service can retry or clean up the same watch. These methods do not automatically
retry subscriptions; `maxRetries` remains specific to ordinary tool calls.

## Unsubscribe

The draft identifies a subscription by the authenticated principal, callback URL,
event name and arguments. The returned `id` is a delivery-routing handle, not an
unsubscribe credential:

```ts
await client.experimental_unsubscribeEvent({
  name: params.name,
  arguments: params.arguments,
  delivery: { url: params.delivery.url },
});
```

Use the same authorized account and original request tuple. The secret is not
sent on unsubscribe. No-expiry subscriptions must be explicitly stopped when the
application no longer needs them.

All three methods accept `options: { signal, timeout, maxTotalTimeout }`, matching
the other MCP client methods. This implementation supports catalog discovery and
webhook control requests only; it does not implement `events/poll`, `events/stream`,
automatic replay recovery or webhook delivery verification.
