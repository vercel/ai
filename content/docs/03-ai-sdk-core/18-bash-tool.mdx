# Bash Tool

The `@ai-sdk/tools/bash` entry point provides a bash tool for any model supporting
function calling. Supply an `Experimental_SandboxSession` to choose where commands
run. Use `@ai-sdk/sandbox-just-bash` for an in-memory environment,
`@ai-sdk/sandbox-vercel` for Vercel Sandbox, or your own implementation.

The tool has no direct dependency on either runtime.

## Installation

Install the tool and the sandbox adapter you want to use:

```sh
pnpm add ai @ai-sdk/tools @ai-sdk/sandbox-just-bash
```

Requires Node.js 22.13 or newer.

## Usage

```ts
import { createJustBashNetworkSandboxSession } from '@ai-sdk/sandbox-just-bash';
import { createBashTool } from '@ai-sdk/tools/bash';
import { generateText, isStepCount } from 'ai';

const session = await createJustBashNetworkSandboxSession();

try {
  const { bash, sandbox } = await createBashTool({
    sandbox: session.restricted(),
    files: { 'notes.txt': 'Apples: 10\nPears: 20\n' },
  });

  const result = await generateText({
    model, // Your configured model with function calling support.
    tools: { bash },
    stopWhen: isStepCount(5),
    prompt: 'Read notes.txt and write a summary to summary.txt.',
  });

  console.log(result.text);
  console.log(await sandbox.readFile('/workspace/summary.txt'));
} finally {
  await session.destroy();
}
```

## Vercel Sandbox

Install `@ai-sdk/sandbox-vercel` and `@vercel/sandbox` to use an existing native
Vercel Sandbox. Wrap it with the adapter before passing it to the tool:

```ts
import { createVercelSandboxSessionFromNativeSandbox } from '@ai-sdk/sandbox-vercel';
import { createBashTool } from '@ai-sdk/tools/bash';
import { Sandbox } from '@vercel/sandbox';

const nativeSandbox = await Sandbox.create();

try {
  const { bash } = await createBashTool({
    sandbox: createVercelSandboxSessionFromNativeSandbox(nativeSandbox),
    workingDirectory: '/vercel/sandbox/workspace',
    files: { 'notes.txt': 'Hello from Vercel Sandbox' },
  });

  // Use bash with generateText, streamText, or ToolLoopAgent here.
} finally {
  await nativeSandbox.stop();
}
```

You can also create a managed session with
`createVercelNetworkSandboxSession()` from `@ai-sdk/sandbox-vercel` and pass
`session.restricted()`. For an existing native just-bash `Sandbox`, use
`createJustBashSandboxSessionFromNativeSandbox()` from `@ai-sdk/sandbox-just-bash`.
Raw runtime instances need their respective adapters; a custom
`Experimental_SandboxSession` can be passed directly.

## Options

`createBashTool()` requires an options object:

| Option             | Type                          | Description                                                                                                                         |
| ------------------ | ----------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `sandbox`          | `Experimental_SandboxSession` | Required session for command execution and file operations.                                                                         |
| `files`            | `Record<string, string>`      | UTF-8 files to write before returning, relative to `workingDirectory`. Existing files at these paths are overwritten.               |
| `workingDirectory` | `string`                      | Absolute starting directory for each command. Defaults to `/workspace`; created if needed. Choose a writable path for your sandbox. |
| `maxOutputLength`  | `number`                      | Positive integer limiting characters retained from each output stream before a truncation notice. Defaults to `30000`.              |

The model calls the tool with `{ command: string }` and receives
`{ stdout, stderr, exitCode }`. Nonzero exit codes are returned so the model can
inspect failures and recover. AI SDK cancellation is forwarded to the session.
Output truncation happens after execution and does not limit execution memory or
duration.

## Files and lifecycle

Initial file paths must stay within `workingDirectory`. This validation applies
to initialization paths; the sandbox controls which files commands can access.
Each command starts in `workingDirectory`. Available programs, network access,
shell state, and persistence depend on the supplied sandbox. Its description is
included in the tool's instructions.

Tools using the same session share files. Creating a tool does not reset existing
files or create a new sandbox. Use separate sessions for independent workflows.
The caller creates, reconnects, and destroys the sandbox.

The returned `sandbox.readFile(path)` handle reads generated UTF-8 text and throws
if the file is missing. You can also use the supplied session's
`readTextFile({ path })`, which returns `null` for a missing file, and its other
file operations. The returned handle is not exposed as a model tool.
