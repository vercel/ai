# Glossary

Use these terms consistently when reading or writing AI SDK documentation,
examples, and code.

## Core Concepts

| Term                   | Meaning                                                                                                                                    |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| AI function            | A user-facing SDK function that performs a language model call, such as `generateText`, `streamText`, `generateObject`, or `embed`.        |
| Language model call    | One invocation of a language model through an AI function or agent step. Prefer this term when you mean a single request to the model.     |
| Model                  | A concrete model instance passed to an AI function, usually created by a provider, for example `openai('gpt-4.1')`.                        |
| Model ID               | A provider-specific string that identifies a model variant, for example `gpt-4.1` or `claude-sonnet-4-5`.                                  |
| Provider               | A package or provider instance that creates model instances for a specific AI service, such as `@ai-sdk/openai` or `@ai-sdk/anthropic`.    |
| Provider specification | The interface contract that providers implement, such as `LanguageModelV4`, `EmbeddingModelV4`, or `ImageModelV4` from `@ai-sdk/provider`. |
| Provider options       | Provider-specific settings passed through `providerOptions`, keyed by provider name, without being interpreted by the core SDK.            |

## Prompts And Messages

| Term              | Meaning                                                                                                                           |
| ----------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| Prompt            | The complete input sent to an AI function, including a prompt string or messages, plus optional system instructions and settings. |
| Message           | A role-based unit of conversation, such as a system, user, assistant, or tool message.                                            |
| Content part      | A typed piece of message content, such as text, file, image, reasoning, tool call, or tool result content.                        |
| System message    | A message that defines high-level behavior or constraints for the model.                                                          |
| Assistant message | A message generated by the model. It can contain text, reasoning, tool calls, and other assistant-authored content.               |
| Tool message      | A message that returns tool results to the model after tool calls have been executed.                                             |

## Tools

| Term                   | Meaning                                                                                                            |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------ |
| Tool                   | A callable capability described to the model with a name, optional description, and input schema.                  |
| Tool call              | A model request to invoke a tool with a specific input and tool call ID.                                           |
| Tool result            | The output returned after executing a tool call.                                                                   |
| Tool choice            | Configuration that controls tool selection, such as `auto`, `none`, `required`, or a specific tool.                |
| Dynamic tool           | A tool whose schema is not statically known when the TypeScript type is declared, such as many MCP-provided tools. |
| Provider-executed tool | A tool that is executed by the provider instead of by your application code.                                       |

## Streaming And Lifecycle

| Term          | Meaning                                                                                                                 |
| ------------- | ----------------------------------------------------------------------------------------------------------------------- |
| Stream        | An incremental sequence of typed parts emitted while a model call is in progress.                                       |
| Stream part   | One typed item in a stream, such as `text-delta`, `tool-call`, `finish`, or `error`.                                    |
| Delta         | An incremental fragment of text, reasoning, or tool input.                                                              |
| Step          | One model invocation inside a multi-step generation or agent loop.                                                      |
| Finish reason | The reason a model call or step stopped, such as `stop`, `length`, `tool-calls`, `content-filter`, `error`, or `other`. |
| Callback      | A function invoked by the SDK during a lifecycle event, such as `onError`, `onFinish`, `onStepFinish`, or `onToolCall`. |
