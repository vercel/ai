# `WebMCPTransport`

Adapts the experimental [WebMCP browser API](https://webmachinelearning.github.io/webmcp/)
to `createMCPClient`. It translates MCP initialization, tool discovery, and tool
calls into `ModelContext` operations, without starting a network MCP server.

```ts
import { createMCPClient, WebMCPTransport } from '@ai-sdk/mcp';

// Browser code. Check that the experimental API is available first.
const client = await createMCPClient({
  transport: new WebMCPTransport({
    modelContext: document.modelContext,
    // Optional: discover tools explicitly exposed by additional frame origins.
    fromOrigins: ['https://widget.example'],
  }),
});

const definitions = await client.listTools();
const tools = await client.tools();

// After the agent finishes and no tool calls are pending:
await client.close();
```

## Parameters

- **`modelContext: WebMCPModelContext`** (required): an object with WebMCP's
  `getTools(options?)` and `executeTool(tool, inputObject?, options?)` methods.
  In a browser, pass `document.modelContext`. For a backend integration, the
  application must supply a bridge implementing these methods against an
  authenticated browser connection. The transport does not open or locate tabs.
  A bridge must preserve stable owner handles across discovery calls and forward
  cancellation to the browser explicitly.
- **`fromOrigins: string[]`** (optional): additional origins passed to
  `getTools`. Browser origin exposure and the `tools` Permissions Policy still
  apply. Omitting this option uses the browser's default same-origin discovery.

The package exports structural `WebMCPModelContext` and `WebMCPTool` types;
it does not add declarations to global DOM interfaces. Use browser API typings
such as `webmcp-types` for `document.modelContext` in TypeScript applications.

## Tool discovery and identity

Tools keep their registered names when available. When names collide across
frames, the transport assigns suffixes such as `getCart_2`. These aliases stay
bound to the same owner window, origin, and original name until the transport
closes. Calls use the original discovered tool dictionary, including its owner
handle. Use the names returned by `listTools` or the keys returned by `tools`.

Input and output schemas are included in discovery. An omitted input schema
becomes an empty object schema. The MCP client's normal schema conversion rules
still apply; automatic discovery does not validate output against its declared
schema. Supply explicit `schemas` to `client.tools` to validate typed outputs.

The standard `readOnlyHint` annotation is forwarded. All WebMCP annotations,
the original name, and origin are preserved under
`tool._meta['ai-sdk.dev/webmcp']`. These are site-provided hints, not permission
grants. An application can inspect them when filtering tools or applying approval
policies. Owner window handles are never included in MCP tool definitions.

## Results, failures, and cancellation

WebMCP returns JSON-serialized values. The transport parses them safely and
returns both text `content` and the parsed value as `structuredContent`. It does
not interpret application objects containing `content` or `isError` as MCP
envelopes. String values become text without an extra layer of JSON quotes.

WebMCP `OperationError` failures become MCP tool results with `isError: true`.
Other discovery or execution failures reject the MCP request. Malformed JSON
results also reject the request. Browser exception names are available as
`MCPClientError.data.name` when supplied by the underlying context.

Tool execution receives the request's `AbortSignal`. Closing the transport aborts
pending executions and releases its tool registry. It does not unregister the
page's tools; registration lifetime belongs to the page.

## Browser and backend usage

An MCP client created with `document.modelContext` runs in that browser. For
backend model inference, forward descriptions and schemas to your API route,
execute tool calls in `useChat.onToolCall`, and submit results using
`addToolOutput`.

Tool lists are snapshots. Call `client.listTools()` or `client.tools()` again
after a WebMCP `toolchange` event, or before each model request. Updating a list
does not replace tools already passed to an ongoing AI SDK generation. This
transport does not implement notifications, streaming tool results, resources,
or prompts.
