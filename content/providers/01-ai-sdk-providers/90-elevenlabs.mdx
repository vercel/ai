# ElevenLabs Provider

The [ElevenLabs](https://elevenlabs.io/) provider contains language model support for the ElevenLabs transcription and speech generation APIs.
ElevenLabs models are not currently available through [AI Gateway](https://vercel.com/ai-gateway/models), so the opening example uses `@ai-sdk/elevenlabs` directly. See [Using AI Gateway](#using-ai-gateway) below for supported alternatives.

```ts
import { generateSpeech } from 'ai';
import { elevenLabs } from '@ai-sdk/elevenlabs';
import { writeFile } from 'node:fs/promises';

const { audio } = await generateSpeech({
  model: elevenLabs.speech('eleven_multilingual_v2'),
  text: 'Hello, world!',
  outputFormat: 'mp3',
  voice: '21m00Tcm4TlvDq8ikWAM',
});

await writeFile('speech.mp3', audio.uint8Array);
```

## Using AI Gateway

The current [AI Gateway model catalog](https://vercel.com/ai-gateway/models) does not list ElevenLabs models. Use `@ai-sdk/elevenlabs` for the APIs on this page. To use other speech models through Gateway, install `ai` and configure a Gateway API key:

```bash

```

See the [Gateway documentation](/providers/ai-sdk-providers/ai-gateway) for supported models and APIs.

## Provider Instance

You can import the default provider instance `elevenLabs` from `@ai-sdk/elevenlabs`:

```ts
import { elevenLabs } from '@ai-sdk/elevenlabs';
```

If you need a customized setup, you can import `createElevenLabs` from `@ai-sdk/elevenlabs` and create a provider instance with your settings:

```ts
import { createElevenLabs } from '@ai-sdk/elevenlabs';

const elevenLabs = createElevenLabs({
  // custom settings, e.g.
  fetch: customFetch,
});
```

You can use the following optional settings to customize the ElevenLabs provider instance:

- **apiKey** _string_

  API key that is being sent using the `xi-api-key` header.
  It defaults to the `ELEVENLABS_API_KEY` environment variable.

- **headers** _Record&lt;string,string&gt;_

  Custom headers to include in the requests.

- **fetch** _(input: RequestInfo, init?: RequestInit) => Promise&lt;Response&gt;_

  Custom [fetch](https://developer.mozilla.org/en-US/docs/Web/API/fetch) implementation.
  Defaults to the global `fetch` function.
  You can use it as a middleware to intercept requests,
  or to provide a custom fetch implementation for e.g. testing.

- **webSocket** _WebSocketConstructor_

  Custom WebSocket implementation for realtime transcription. A
  header-capable implementation is required in runtimes whose native WebSocket
  constructor cannot send the `xi-api-key` authentication header.

## Speech Models

You can create models that call the [ElevenLabs speech API](https://elevenlabs.io/text-to-speech)
using the `.speech()` factory method.

The first argument is the model id e.g. `eleven_multilingual_v2`.

```ts
const model = elevenLabs.speech('eleven_multilingual_v2');
```

The `voice` argument can be set to a voice ID from the [ElevenLabs Voice Library](https://elevenlabs.io/app/voice-library).
You can find voice IDs by selecting a voice in the library and copying its ID.

```ts highlight="6"
import { generateSpeech } from 'ai';
import { elevenLabs } from '@ai-sdk/elevenlabs';

const result = await generateSpeech({
  model: elevenLabs.speech('eleven_multilingual_v2'),
  text: 'Hello, world!',
  voice: '21m00Tcm4TlvDq8ikWAM', // Rachel voice
});
```

You can also pass additional provider-specific options using the `providerOptions` argument:

```ts highlight="7-9"
import { generateSpeech } from 'ai';
import {
  elevenLabs,
  type ElevenLabsSpeechModelOptions,
} from '@ai-sdk/elevenlabs';

const result = await generateSpeech({
  model: elevenLabs.speech('eleven_multilingual_v2'),
  text: 'Hello, world!',
  voice: '21m00Tcm4TlvDq8ikWAM',
  providerOptions: {
    elevenlabs: {
      voiceSettings: {
        stability: 0.5,
        similarityBoost: 0.75,
      },
    } satisfies ElevenLabsSpeechModelOptions,
  },
});
```

- **withTimestamps** _boolean_

  Return speech character alignment or music lyric word timestamps alongside
  the generated audio. Defaults to `false`. Timestamps are available in
  `result.providerMetadata.elevenlabs`.

- **languageCode** _string or null_  
  Optional. Language code (ISO 639-1) used to enforce a language for the model. Currently, only Turbo v2.5 and Flash v2.5 support language enforcement. For other models, providing a language code will result in an error.

- **voiceSettings** _object or null_  
  Optional. Voice settings that override stored settings for the given voice. These are applied only to the current request.
  - **stability** _double or null_  
    Optional. Determines how stable the voice is and the randomness between each generation. Lower values introduce broader emotional range; higher values result in a more monotonous voice.
  - **useSpeakerBoost** _boolean or null_  
    Optional. Boosts similarity to the original speaker. Increases computational load and latency.
  - **similarityBoost** _double or null_  
    Optional. Controls how closely the AI should adhere to the original voice.
  - **style** _double or null_  
    Optional. Amplifies the style of the original speaker. May increase latency if set above 0.

- **pronunciationDictionaryLocators** _array of objects or null_  
  Optional. A list of pronunciation dictionary locators to apply to the text, in order. Up to 3 locators per request.  
  Each locator object:
  - **pronunciationDictionaryId** _string_ (required)  
    The ID of the pronunciation dictionary.
  - **versionId** _string or null_ (optional)  
    The version ID of the dictionary. If not provided, the latest version is used.

- **seed** _integer or null_  
  Optional. If specified, the system will attempt to sample deterministically. Must be between 0 and 4294967295. Determinism is not guaranteed.

- **previousText** _string or null_  
  Optional. The text that came before the current request's text. Can improve continuity when concatenating generations or influence current generation continuity.

- **nextText** _string or null_  
  Optional. The text that comes after the current request's text. Can improve continuity when concatenating generations or influence current generation continuity.

- **previousRequestIds** _array of strings or null_  
  Optional. List of request IDs for samples generated before this one. Improves continuity when splitting large tasks. Max 3 IDs. If both `previousText` and `previousRequestIds` are sent, `previousText` is ignored.

- **nextRequestIds** _array of strings or null_  
  Optional. List of request IDs for samples generated after this one. Useful for maintaining continuity when regenerating a sample. Max 3 IDs. If both `nextText` and `nextRequestIds` are sent, `nextText` is ignored.

- **applyTextNormalization** _enum_  
  Optional. Controls text normalization.  
  Allowed values: `'auto'` (default), `'on'`, `'off'`.
  - `'auto'`: System decides whether to apply normalization (e.g., spelling out numbers).
  - `'on'`: Always apply normalization.
  - `'off'`: Never apply normalization.  
    For `eleven_turbo_v2_5` and `eleven_flash_v2_5`, can only be enabled with Enterprise plans.

- **applyLanguageTextNormalization** _boolean_  
  Optional. Defaults to `false`. Controls language text normalization, which helps with proper pronunciation in some supported languages (currently only Japanese). May significantly increase latency.

- **enableLogging** _boolean_  
  Optional. Whether to enable request logging for this API call. Defaults to the account-level setting.

### Speech Timestamps

Set `withTimestamps` to receive character-level alignment for both the original
and normalized text:

```ts
import { elevenLabs } from '@ai-sdk/elevenlabs';
import { generateSpeech } from 'ai';

const result = await generateSpeech({
  model: elevenLabs.speech('eleven_v4'),
  text: 'Hello from ElevenLabs!',
  voice: 'JBFqnCBsd6RMkjVDRZzb',
  providerOptions: {
    elevenlabs: { withTimestamps: true },
  },
});

console.log(result.providerMetadata?.elevenlabs);
```

The audio remains available in `result.audio`. Provider metadata contains:

- `alignment`: original text `characters`, `characterStartTimesSeconds`, and
  `characterEndTimesSeconds` arrays.
- `normalizedAlignment`: the same fields for normalized text, such as spoken
  numbers and dates.
- `voiceSegments`: for Text to Dialogue responses, the `voiceId`,
  `startTimeSeconds`, `endTimeSeconds`, `characterStartIndex`,
  `characterEndIndex` (exclusive), and `dialogueInputIndex` for each segment.

Times are in seconds. Alignment and voice segments are included only when
supplied by ElevenLabs; empty arrays are preserved.

For multi-voice dialogue, combine `withTimestamps` with `inputs`. The returned
`voiceSegments` associate each segment with its voice and input index. This
option applies to `generateSpeech`. Sound effects ignore it and produce a warning.

`eleven_v4` automatically uses the Text to Dialogue API with a single input
containing `text` and `voice`, with or without timestamps. `voiceSettings.stability`
and `voiceSettings.similarityBoost` map to dialogue settings. The `speed`,
`voiceSettings.style`, `voiceSettings.useSpeakerBoost`, and
`applyLanguageTextNormalization` options are unsupported on this route and
produce warnings. `previousText` and `nextText` map to `previous_text` and
`future_text`; the dialogue API limits each to 100 characters.

Other speech models use the Text to Speech API and its `/with-timestamps`
variant when enabled. This includes `eleven_multilingual_v2`, `eleven_v3`,
`eleven_flash_v2_5`, and `eleven_flash_v2`.

### Dialogue

Set `providerOptions.elevenlabs.inputs` to generate multi-speaker dialogue with
the [Text-to-Dialogue API](https://elevenlabs.io/docs/api-reference/text-to-dialogue/convert)
and an `eleven_v3` or `eleven_v4` model. Each input pairs a line of text with
the voice that speaks it. The inputs replace `text` and `voice`: pass an empty
`text`; a non-empty `text` or a `voice` is ignored with a warning.

```ts
const result = await generateSpeech({
  model: elevenLabs.speech('eleven_v3'),
  text: '',
  providerOptions: {
    elevenlabs: {
      inputs: [
        { text: '[giggling] Knock knock', voiceId: alice },
        { text: '[curious] Who is there?', voiceId: bob },
      ],
      voiceSettings: { stability: 0.5, similarityBoost: 0.75 },
    } satisfies ElevenLabsSpeechModelOptions,
  },
});
```

`voiceSettings.stability` and `voiceSettings.similarityBoost` map to the
dialogue `settings`; `nextText` is sent as `future_text`. `speed`,
`voiceSettings.style`, `voiceSettings.useSpeakerBoost`, and
`applyLanguageTextNormalization` are ignored with a warning.

### Music

The `music_*` models compose music with the
[Music API](https://elevenlabs.io/docs/api-reference/music/compose). `text` is
the music prompt; `voice`, `speed`, `language`, and the text-to-speech options
are ignored with a warning. The Music API requires a paid ElevenLabs plan.

```ts
const result = await generateSpeech({
  model: elevenLabs.speech('music_v2_5'),
  text: 'An upbeat synthwave intro with driving bass',
  providerOptions: {
    elevenlabs: {
      musicLengthMs: 10000,
      forceInstrumental: true,
    } satisfies ElevenLabsSpeechModelOptions,
  },
});
```

- **musicLengthMs** _integer_  
  Optional. Length of the song in milliseconds, between 3000 and 600000. When
  omitted, the model picks a length from the prompt.

- **forceInstrumental** _boolean_  
  Optional. Guarantees an instrumental song.

- **compositionPlan** _object_  
  Optional. A native ElevenLabs `composition_plan` (snake_case), validated and
  sent in place of the prompt: `sections` for `music_v1`, `chunks` (generation
  and audio-reference chunks) for `music_v2` and later. It cannot be combined
  with `musicLengthMs` or `forceInstrumental`. `seed` is only accepted with a
  composition plan.

When the length is known, from `musicLengthMs` or the plan's sections or
chunks, it is reported in `providerMetadata.elevenlabs.requestedDurationMs`.

#### Lyric timestamps

Set `providerOptions.elevenlabs.withTimestamps` to `true` with a music model to
return lyric timing alongside the audio. This uses the detailed music endpoint
and preserves the normal `result.audio` output.

`result.providerMetadata.elevenlabs.wordTimestamps` contains an array of
`{ word, startMs, endMs }` objects. Unlike speech alignment, these times are in
milliseconds. Empty arrays are preserved; the field is omitted when the provider
does not supply lyric timing. Both text prompts and composition plans are
supported.

### Sound effects

The `eleven_text_to_sound_*` models generate sound effects with the
[Sound Effects API](https://elevenlabs.io/docs/api-reference/text-to-sound-effects/convert).
`text` describes the sound; `voice`, `speed`, `language`, `seed`, and the
text-to-speech options are ignored with a warning.

```ts
const result = await generateSpeech({
  model: elevenLabs.speech('eleven_text_to_sound_v2'),
  text: 'Glass shattering on a concrete floor',
  providerOptions: {
    elevenlabs: {
      durationSeconds: 2,
      promptInfluence: 0.5,
    } satisfies ElevenLabsSpeechModelOptions,
  },
});
```

- **durationSeconds** _number_  
  Optional. Length of the sound between 0.5 and 30 seconds. When omitted, the
  model picks a length from the prompt.

- **promptInfluence** _number_  
  Optional. How closely the sound follows the prompt, from 0 to 1. Defaults to
  0.3.

- **loop** _boolean_  
  Optional. Creates a sound that loops smoothly.

Music and sound effects models do not stream; `experimental_streamSpeech`
throws an `UnsupportedFunctionalityError`. Streaming speech ignores the
`inputs`, music, and sound effects options with a warning.

## Streaming Speech Models

<Note type="warning">Streaming speech is an experimental feature.</Note>

`experimental_streamSpeech` uses the ElevenLabs text-to-speech WebSocket
(`stream-input`). Text deltas are forwarded as they arrive, so you can pipe an
LLM text stream straight into speech, and audio chunks stream back as they are
generated.

```ts
import { elevenLabs } from '@ai-sdk/elevenlabs';
import { experimental_streamSpeech as streamSpeech, streamText } from 'ai';

const { textStream } = streamText({
  model: 'openai/gpt-5.4-nano',
  prompt: 'In three sentences, explain why the sky is blue.',
});

const result = streamSpeech({
  model: elevenLabs.speech('eleven_flash_v2_5'),
  text: textStream, // a string, or an array or stream of strings and/or text parts
  voice: '21m00Tcm4TlvDq8ikWAM',
  outputFormat: { type: 'audio/pcm', rate: 24000 },
  providerOptions: {
    elevenlabs: {
      streaming: {
        chunkLengthSchedule: [50, 120, 160],
        syncAlignment: true,
      },
    },
  },
});

for await (const part of result.fullStream) {
  if (part.type === 'audio') {
    // part.audio: Uint8Array, part.audioFormat: { type: 'audio/pcm', rate: 24000 }
  }
}

console.log(await result.usage); // { inputCharacters: ... }
```

The API key is sent in the WebSocket's first message, so the native
`WebSocket` works in every runtime. Run streaming speech on the server: in
browser code the API key would be exposed to the client.

`outputFormat` maps to an ElevenLabs `output_format`: `audio/mpeg` (44.1 kHz,
or 22.05 kHz), `audio/pcm` (8, 16, 22.05, 24 (default), 44.1, or 48 kHz),
`audio/pcmu` and `audio/pcma` (8 kHz), and `audio/opus` or `audio/ogg` (48 kHz
Opus, delivered in an Ogg container and reported as `audio/ogg`). Other formats
are rejected. Set `providerOptions.elevenlabs.streaming.outputFormat` to a
native ElevenLabs format (for example `mp3_44100_192`) to choose one directly.
Without either, audio is `mp3_44100_128`.

The text-to-speech WebSocket speaks one voice per stream. A text part whose
`voice` differs from the call's `voice` errors the stream; use dialogue
(below) for several voices.

Text deltas that end mid-word (common in LLM streams) are held back until the
next whitespace before they are sent, and the rest is flushed when the text
stream ends. CJK sentence punctuation also counts as a boundary, and held text
is sent after 100 characters regardless. While the text stream is idle, the
provider sends keepalive messages so the connection outlives the server's
default inactivity timeout (for example while a reasoning model thinks).
Setting `inactivityTimeout` turns keepalives off, so the timeout you set
applies.

`usage.inputCharacters` is the number of Unicode code points sent for synthesis.
Audio parts carry ElevenLabs `alignment` and `normalizedAlignment` data in
`providerMetadata.elevenlabs` when the server returns it.

The `streaming` provider options mirror the WebSocket settings: `autoMode`,
`chunkLengthSchedule`, `enableSsmlParsing`, `inactivityTimeout` (seconds, up to
180), `outputFormat`, and `syncAlignment`. `generateSpeech` ignores them with a
warning. `voiceSettings`, `pronunciationDictionaryLocators`,
`seed`, `applyTextNormalization`, `languageCode`, and `enableLogging` apply as
for `generateSpeech`. `previousText`, `nextText`, `previousRequestIds`,
`nextRequestIds`, and `applyLanguageTextNormalization` are not supported over
the WebSocket and produce warnings.

See the speech model capabilities table above for which models stream. The
`eleven_v3` and `eleven_v4` model families are not served by the
text-to-speech WebSocket; stream them as dialogue (below).

### Streaming dialogue

Set `providerOptions.elevenlabs.dialogue` to stream multi-speaker dialogue over
the Text-to-Dialogue WebSocket with an `eleven_v3` or `eleven_v4` model. List
the voices in `dialogue.voices` (the socket needs them up front), then give each
text part its speaker with `voice`. Parts without a `voice` use the call's
`voice`, or else the first dialogue voice; a voice that is not listed errors the
stream. A change of voice starts a new turn. To start a new turn with the same
voice, set `providerOptions: { elevenlabs: { newTurn: true } }` on the part.

```ts
const result = streamSpeech({
  model: elevenLabs.speech('eleven_v4'),
  // An array, or a stream of parts arriving from an LLM.
  text: [
    {
      type: 'text',
      text: 'Did you hear we can stream dialogue now? ',
      voice: alice,
    },
    { type: 'text', text: 'Over one socket? That is neat.', voice: bob },
  ],
  providerOptions: {
    elevenlabs: {
      dialogue: { voices: [alice, bob], voiceSettings: { stability: 0.5 } },
    },
  },
});
```

Text is held back to word boundaries within each speaker's text and flushed
when the speaker changes. Text-to-Dialogue ignores `speed`, top-level
`voiceSettings` (use `dialogue.voiceSettings.stability`), and the `autoMode`,
`chunkLengthSchedule`, `enableSsmlParsing`, and `inactivityTimeout` streaming
options; each produces a warning. `eleven_v4` models receive the text incrementally.
`eleven_v3` models accept a single message per dialogue session, so the
provider reads the whole text stream before sending it.
`eleven_v3_conversational` supports a single voice. Text-to-Dialogue has a fixed
inactivity timeout, so keepalives are always sent while the text stream is idle.
Audio parts carry `alignment` (camelCase) and `isFinalAudioForTurn` in
`providerMetadata.elevenlabs` when the server returns them; a turn boundary
without audio arrives as an empty audio part carrying only `isFinalAudioForTurn`.

## Transcription Models

You can create models that call the [ElevenLabs transcription API](https://elevenlabs.io/speech-to-text)
using the `.transcription()` factory method.

The first argument is the model id e.g. `scribe_v2`.

```ts
const model = elevenLabs.transcription('scribe_v2');
```

You can also pass additional provider-specific options using the `providerOptions` argument. For example, supplying the input language in ISO-639-1 (e.g. `en`) format can sometimes improve transcription performance if known beforehand.

```ts highlight="10-14"
import { transcribe } from 'ai';
import {
  elevenLabs,
  type ElevenLabsTranscriptionModelOptions,
} from '@ai-sdk/elevenlabs';

const result = await transcribe({
  model: elevenLabs.transcription('scribe_v2'),
  audio: new Uint8Array([1, 2, 3, 4]),
  providerOptions: {
    elevenlabs: {
      languageCode: 'en',
    } satisfies ElevenLabsTranscriptionModelOptions,
  },
});
```

The following provider options are available:

- **languageCode** _string_

  An ISO-639-1 or ISO-639-3 language code corresponding to the language of the audio file.
  Can sometimes improve transcription performance if known beforehand.
  Defaults to `null`, in which case the language is predicted automatically.

- **tagAudioEvents** _boolean_

  Whether to tag audio events like (laughter), (footsteps), etc. in the transcription.
  Defaults to `true`.

- **numSpeakers** _integer_

  The maximum amount of speakers talking in the uploaded file.
  Can help with predicting who speaks when.
  The maximum amount of speakers that can be predicted is 32.
  Defaults to `null`, in which case the amount of speakers is set to the maximum value the model supports.

- **timestampsGranularity** _enum_

  The granularity of the timestamps in the transcription.
  Defaults to `'word'`.
  Allowed values: `'none'`, `'word'`, `'character'`.

- **diarize** _boolean_

  Whether to annotate which speaker is currently talking in the uploaded file.
  Defaults to `true`.

- **fileFormat** _enum_

  The format of input audio.
  Defaults to `'other'`.
  Allowed values: `'pcm_s16le_16'`, `'other'`.
  For `'pcm_s16le_16'`, the input audio must be 16-bit PCM at a 16kHz sample rate, single channel (mono), and little-endian byte order.
  Latency will be lower than with passing an encoded waveform.

### Transcription Timestamps

Scribe batch transcription returns word timing in `result.segments`, using
`startSecond` and `endSecond`. Word timestamps are requested by default.
Use `timestampsGranularity: 'character'` for character timing as well:

```ts
providerOptions: {
  elevenlabs: { timestampsGranularity: 'character' },
},
```

`result.providerMetadata.elevenlabs.words` preserves each token's native
`start`, `end`, `type`, `speaker_id`, and optional `characters` array. Each
character has `text`, `start`, and `end`; these times are in seconds.
For realtime Scribe, set `streaming.includeTimestamps: true` and read the
timestamped word segments from `await result.segments` after the stream finishes.

## Streaming Transcription Models

<Note type="warning">Streaming transcription is an experimental feature.</Note>

Scribe v2 Realtime supports live transcription through
`experimental_streamTranscribe`. It accepts raw PCM audio at 8, 16, 22.05, 24,
44.1, or 48 kHz, or 8 kHz mu-law audio.

```ts
import {
  createElevenLabs,
  type ElevenLabsProviderSettings,
} from '@ai-sdk/elevenlabs';
import { experimental_streamTranscribe as streamTranscribe } from 'ai';
import { WebSocket } from 'ws';

const elevenLabs = createElevenLabs({
  webSocket: WebSocket as unknown as ElevenLabsProviderSettings['webSocket'],
});

const result = streamTranscribe({
  model: elevenLabs.transcription('scribe_v2_realtime'),
  audio,
  inputAudioFormat: { type: 'audio/pcm', rate: 16000 },
  providerOptions: {
    elevenlabs: {
      languageCode: 'en',
      streaming: {
        includeLanguageDetection: true,
        includeTimestamps: true,
      },
    },
  },
});

for await (const part of result.fullStream) {
  if (part.type === 'transcript-partial') {
    console.log('partial:', part.text);
  }

  if (part.type === 'transcript-final') {
    console.log('final:', part.text);
  }
}
```

The ElevenLabs realtime endpoint authenticates with a WebSocket header. Use a
header-capable WebSocket implementation, such as `ws`, in runtimes whose native
WebSocket constructor cannot send headers.

The `streaming` provider options mirror ElevenLabs' realtime transcription
settings: `commitStrategy`, `enableLogging`, `filterBackgroundAudio`,
`includeLanguageDetection`, `includeTimestamps`, `keyterms`,
`minSilenceDurationMs`, `minSpeechDurationMs`, `noVerbatim`, `previousText`,
`secondaryLanguages`, `vadSilenceThresholdSecs`, and `vadThreshold`.

ElevenLabs delivers detected language on its timestamp-bearing committed event.
When `includeLanguageDetection` is enabled, the provider requests that event
internally, but only returns timestamp segments when `includeTimestamps` is also
enabled. `filterBackgroundAudio` cannot be combined with either option.

See [Transcription](/docs/ai-sdk-core/transcription) for more information about
streaming transcription.
