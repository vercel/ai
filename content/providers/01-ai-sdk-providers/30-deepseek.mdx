# DeepSeek Provider

The [DeepSeek](https://www.deepseek.com) provider offers access to powerful language models through the DeepSeek API.

API keys can be obtained from the [DeepSeek Platform](https://platform.deepseek.com/api_keys).

## Setup

The DeepSeek provider is available via the `@ai-sdk/deepseek` module. You can install it with:

<InstallPackages packages="@ai-sdk/deepseek" />

## Provider Instance

You can import the default provider instance `deepSeek` from `@ai-sdk/deepseek`:

```ts
import { deepSeek } from '@ai-sdk/deepseek';
```

For custom configuration, you can import `createDeepSeek` and create a provider instance with your settings:

```ts
import { createDeepSeek } from '@ai-sdk/deepseek';

const deepSeek = createDeepSeek({
  apiKey: process.env.DEEPSEEK_API_KEY ?? '',
});
```

You can use the following optional settings to customize the DeepSeek provider instance:

- **baseURL** _string_

  Use a different URL prefix for API calls.
  The default prefix is `https://api.deepseek.com`.

- **apiKey** _string_

  API key that is being sent using the `Authorization` header. It defaults to
  the `DEEPSEEK_API_KEY` environment variable.

- **headers** _Record&lt;string,string&gt;_

  Custom headers to include in the requests.

- **fetch** _(input: RequestInfo, init?: RequestInit) => Promise&lt;Response&gt;_

  Custom [fetch](https://developer.mozilla.org/en-US/docs/Web/API/fetch) implementation.

## Language Models

You can create language models using a provider instance:

```ts
import { deepSeek } from '@ai-sdk/deepseek';
import { generateText } from 'ai';

const { text } = await generateText({
  model: deepSeek('deepseek-v4-flash'),
  prompt: 'Write a vegetarian lasagna recipe for 4 people.',
});
```

You can also use the `.chat()` or `.languageModel()` factory methods:

```ts
const model = deepSeek.chat('deepseek-v4-flash');
// or
const model = deepSeek.languageModel('deepseek-v4-flash');
```

DeepSeek language models can be used in the `streamText` function
(see [AI SDK Core](/docs/ai-sdk-core)).

The following optional provider options are available for DeepSeek models:

- `thinking` _object_

  Optional. Controls thinking mode (chain-of-thought reasoning). DeepSeek V4
  models use thinking mode by default.
  - `type`: `'adaptive' | 'enabled' | 'disabled'` - Enable or disable thinking.
    DeepSeek's official V4 API supports `enabled` and `disabled`; `adaptive` is
    available for compatible endpoints. See [DeepSeek's thinking mode docs](https://api-docs.deepseek.com/guides/thinking_mode).

- `reasoningEffort` _'low' | 'medium' | 'high' | 'xhigh' | 'max'_

  Optional. Controls thinking strength for DeepSeek V4 models. Per
  DeepSeek's docs, `low` and `medium` are mapped to `high`, and `xhigh` is
  mapped to `max` server-side for compatibility with other providers. When
  using the top-level `reasoning` setting, `minimal` is sent as `low`, and
  `low`, `medium`, `high`, and `xhigh` pass through to DeepSeek's native
  effort values.

```ts highlight="7-12"
import {
  deepSeek,
  type DeepSeekLanguageModelChatOptions,
} from '@ai-sdk/deepseek';
import { generateText } from 'ai';

const { text, reasoning } = await generateText({
  model: deepSeek('deepseek-v4-pro'),
  prompt: 'How many "r"s are in the word "strawberry"?',
  providerOptions: {
    deepseek: {
      thinking: { type: 'enabled' },
      reasoningEffort: 'high',
    } satisfies DeepSeekLanguageModelChatOptions,
  },
});
```

### Reasoning

Both `deepseek-v4-flash` and `deepseek-v4-pro` support thinking and non-thinking
modes. The reasoning is exposed through streaming:

```ts
import { deepSeek } from '@ai-sdk/deepseek';
import { streamText } from 'ai';

const result = streamText({
  model: deepSeek('deepseek-v4-pro'),
  prompt: 'How many "r"s are in the word "strawberry"?',
});

for await (const part of result.stream) {
  if (part.type === 'reasoning') {
    // This is the reasoning text
    console.log('Reasoning:', part.text);
  } else if (part.type === 'text') {
    // This is the final answer
    console.log('Answer:', part.text);
  }
}
```

See [AI SDK UI: Chatbot](/docs/ai-sdk-ui/chatbot#reasoning) for more details
on how to integrate reasoning into your chatbot.

#### Thinking Mode Behavior

DeepSeek V4 uses thinking mode by default. The default reasoning effort is
`high` for regular requests, while DeepSeek may automatically use `max` for
some complex agent requests. Set `thinking.type` to `disabled` when you do not
want reasoning.

<Note>
  In thinking mode, DeepSeek ignores `temperature`, `topP`, `presencePenalty`,
  and `frequencyPenalty`. Supplying these settings does not produce an API
  error, but they have no effect on the response.
</Note>

DeepSeek returns reasoning separately from final text. The AI SDK exposes it as
reasoning parts and serializes those parts back to DeepSeek as
`reasoning_content` in subsequent requests. When a thinking-mode response
contains a tool call, retain the complete assistant response, including its
reasoning parts, in the conversation history. DeepSeek requires that reasoning
content in all subsequent requests and returns a `400` error if it is missing.

When a response does not contain a tool call, reasoning from previous turns is
not required and DeepSeek ignores it if it is included. See [DeepSeek's
thinking mode guide](https://api-docs.deepseek.com/guides/thinking_mode) for
details.

### Multi-turn Conversations

DeepSeek's Chat Completions API is stateless. Send the complete conversation
history with each request. Use `responseMessages` to retain the assistant and
tool messages produced by the AI SDK, including reasoning content required by
thinking-mode tool calls:

```ts
import { deepSeek } from '@ai-sdk/deepseek';
import { generateText, type ModelMessage } from 'ai';

const messages: ModelMessage[] = [
  { role: 'user', content: 'What is the highest mountain in the world?' },
];

const result = await generateText({
  model: deepSeek('deepseek-v4-pro'),
  messages,
});

messages.push(...result.responseMessages);
messages.push({ role: 'user', content: 'What is the second highest?' });
```

See [DeepSeek's multi-round conversation
guide](https://api-docs.deepseek.com/guides/multi_round_chat) for details.

### JSON Output

DeepSeek V4 supports JSON output. When you use an AI SDK `Output` schema, the
provider requests JSON mode and adds the schema instructions to the prompt:

```ts
import { deepSeek } from '@ai-sdk/deepseek';
import { generateText, Output } from 'ai';
import { z } from 'zod';

const result = await generateText({
  model: deepSeek('deepseek-v4-pro'),
  output: Output.object({
    schema: z.object({
      question: z.string(),
      answer: z.string(),
    }),
  }),
  prompt: 'Which is the highest mountain in the world? Mount Everest.',
});

console.log(result.output);
```

Set `maxOutputTokens` high enough to prevent truncated JSON. DeepSeek notes that
JSON mode can occasionally return empty content; adjusting the prompt can help
when this occurs. See [DeepSeek's JSON output
guide](https://api-docs.deepseek.com/guides/json_mode) for details.

### Tool Calls

DeepSeek V4 supports tool calls in both thinking and non-thinking modes. In
thinking mode, retain `responseMessages` across every tool-call step so the
provider can return the required `reasoning_content` to DeepSeek.

DeepSeek also offers strict tool-call schemas as a Beta feature. To use it,
configure the Beta base URL and set `strict: true` on every tool:

```ts
import { createDeepSeek } from '@ai-sdk/deepseek';

const deepSeek = createDeepSeek({
  baseURL: 'https://api.deepseek.com/beta',
});
```

Strict mode supports a subset of JSON Schema and rejects unsupported schemas.
Every object property must be required and every object must set
`additionalProperties` to `false`. See [DeepSeek's tool call
guide](https://api-docs.deepseek.com/guides/tool_calls) for the supported schema
types and constraints.

### Cache Token Usage

DeepSeek's disk-based context caching is enabled automatically for all users.
Requests with prefixes that fully match a persisted cache unit can reuse its
tokens. Cache construction is asynchronous and best-effort, so a reusable
prefix does not guarantee a cache hit.

You can access cache usage through the standard `usage` property or DeepSeek's
provider metadata:

```ts
import { deepSeek } from '@ai-sdk/deepseek';
import { generateText } from 'ai';

const result = await generateText({
  model: deepSeek('deepseek-v4-flash'),
  prompt: 'Your prompt here',
});

console.log(result.providerMetadata);
// Example output: { deepseek: { promptCacheHitTokens: 1856, promptCacheMissTokens: 5 } }

console.log(result.usage.inputTokens.cacheRead);
```

The metrics include:

- `promptCacheHitTokens`: Number of input tokens that were cached
- `promptCacheMissTokens`: Number of input tokens that were not cached

DeepSeek usually clears unused cache entries within a few hours to a few days.
The cache only reuses input prefixes; output is still generated normally.

<Note>
  For more details about DeepSeek's caching system, see the [DeepSeek caching
  documentation](https://api-docs.deepseek.com/guides/kv_cache#checking-cache-hit-status).
</Note>

### Beta Completion APIs

DeepSeek also documents Chat Prefix Completion and Fill-in-the-Middle (FIM)
Completion as Beta APIs. These APIs require the Beta base URL and request fields
or endpoints that `@ai-sdk/deepseek` does not currently expose. Use DeepSeek's
native API client if you need [Chat Prefix
Completion](https://api-docs.deepseek.com/guides/chat_prefix_completion) or
[FIM Completion](https://api-docs.deepseek.com/guides/fim_completion).

## Model Capabilities

| Model               | Text Generation | Object Generation | Image Input | Tool Usage | Tool Streaming |
| ------------------- | --------------- | ----------------- | ----------- | ---------- | -------------- |
| `deepseek-v4-flash` | <Check />       | <Check />         | <Cross />   | <Check />  | <Check />      |
| `deepseek-v4-pro`   | <Check />       | <Check />         | <Cross />   | <Check />  | <Check />      |

Both DeepSeek V4 models have a 1M-token context window, support up to 384K output
tokens, and use thinking mode by default. Set `thinking.type` to `disabled` to
use non-thinking mode.

<Note>
  The legacy `deepseek-chat` and `deepseek-reasoner` model names currently map
  to the non-thinking and thinking modes of `deepseek-v4-flash`, respectively.
  DeepSeek will retire both aliases on 2026-07-24 at 15:59 UTC. Migrate to
  `deepseek-v4-flash` or `deepseek-v4-pro` before then.
</Note>

</Note>
