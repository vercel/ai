# TypeSafe Provider

The [TypeSafe](https://typesafe.ai) provider supports the experimental decision
API with native Choice, Score, and Boolean answers. It sends all questions in one
request against the same state.
You can use TypeSafe models through [AI Gateway](/providers/ai-sdk-providers/ai-gateway) (recommended) or connect directly with `@ai-sdk/typesafe-ai`.

```ts provider="typesafe-ai" model="typesafe-ai/jev"
import { experimental_decide } from 'ai';
__PROVIDER_IMPORT__;

const result = await experimental_decide({
  model: __DECISION_MODEL__,
  state: 'I was charged twice. Please refund the duplicate.',
  questions: {
    requestsRefund: {
      type: 'boolean',
      instructions: 'Is the customer requesting money back?',
    },
  },
});

console.log(result.answers.requestsRefund.probability);
```

## Using AI Gateway

The AI SDK uses AI Gateway by default for model strings. Gateway provides access to models across providers through a single API key, with usage and cost tracking. Install `ai`:

<InstallPackages packages="ai" />

Set an [AI Gateway API key](https://vercel.com/docs/ai-gateway/getting-started) in your environment:

```bash
export AI_GATEWAY_API_KEY=your_api_key_here
```

Vercel deployments can also use [OIDC authentication](/providers/ai-sdk-providers/ai-gateway#oidc-authentication-vercel-deployments).
See the [AI Gateway provider documentation](/providers/ai-sdk-providers/ai-gateway) for configuration and the [model catalog](https://vercel.com/ai-gateway/models) for available models.

Gateway feature and provider-option support depends on the model and the provider serving the request. See [Gateway provider options](https://vercel.com/docs/ai-gateway/models-and-providers/provider-options).

## Using `@ai-sdk/typesafe-ai`

For direct access to TypeSafe, install `ai` and `@ai-sdk/typesafe-ai`:

<InstallPackages packages="ai @ai-sdk/typesafe-ai" />

Set your TypeSafe API credential in the `TYPESAFE_AI_API_KEY` environment variable:

```bash
export TYPESAFE_AI_API_KEY=your_api_key_here
```

Use the direct provider for a custom TypeSafe-compatible endpoint or direct TypeSafe authentication. Both examples use the experimental `experimental_decide` API.

<Note>
  The following sections document the direct `@ai-sdk/typesafe-ai` provider, including its model factories and settings. Gateway model and feature availability can differ.
</Note>

Import the default provider or configure an instance:

```ts
import { createTypeSafeAi, typeSafeAi } from '@ai-sdk/typesafe-ai';

const customTypeSafe = createTypeSafeAi({
  apiKey: 'your-api-key',
});
```

`createTypeSafeAi` accepts:

| Setting   | Description                                                            |
| --------- | ---------------------------------------------------------------------- |
| `apiKey`  | API key; defaults to `TYPESAFE_AI_API_KEY`.                            |
| `baseURL` | Defaults to `TYPESAFE_AI_BASE_URL`, then `https://api.typesafe.ai/v1`. |
| `headers` | Additional request headers.                                            |
| `fetch`   | Custom fetch implementation.                                           |

Use `TYPESAFE_AI_BASE_URL` to route the default `typeSafeAi` instance through a
trusted proxy or self-hosted TypeSafe-compatible server:

```sh
TYPESAFE_AI_BASE_URL=http://127.0.0.1:8766/v1
```

An explicit `baseURL` passed to `createTypeSafeAi` takes precedence over the
environment variable. The configured server receives the API key and decision
state and must implement the TypeSafe `POST /systemone` API.

## Decision

```ts
import { typeSafeAi } from '@ai-sdk/typesafe-ai';
import { experimental_decide } from 'ai';

const result = await experimental_decide({
  model: typeSafeAi.decisionModel('jev-latest'),
  state: {
    message: 'I was charged twice. Please refund the duplicate.',
  },
  questions: {
    department: {
      type: 'choice',
      instructions: 'Which team should handle this?',
      criteria: {
        billing: { includes: ['Charges', 'Invoices', 'Refunds'] },
        technical: ['Bugs', 'Outages'],
        other: null,
      },
    },
    severity: {
      type: 'score',
      instructions: 'How severe is the issue?',
      criteria: ['Cosmetic', 'Workaround exists', 'Blocking; no workaround'],
    },
    requestsRefund: {
      type: 'boolean',
      instructions: 'Is the customer requesting money back?',
    },
  },
});

console.log(result.answers.department.choice);
console.log(result.answers.severity.score);
console.log(result.answers.requestsRefund.probability);
console.log(result.usage);
```

Use `jev-latest` or another TypeSafe model ID. The response includes the actual
model ID, such as the resolved version behind the alias. Use model instances,
custom aliases, or registered providers. With `typeSafeAi` explicitly configured
as `globalThis.AI_SDK_DEFAULT_PROVIDER`, you can pass `model: 'jev-latest'`
directly. See [model aliases and registries](/docs/ai-sdk-core/decisions#model-aliases-and-registries).

| Question  | Native TypeSafe primitive | Limits and semantics                                                 |
| --------- | ------------------------- | -------------------------------------------------------------------- |
| `choice`  | Choice                    | 1–255 options; selected option and full probabilities.               |
| `score`   | Score                     | 2–10 ordered rubric levels; fractional score and full probabilities. |
| `boolean` | Noul                      | Required model-estimated probability of true.                        |

State, instructions, and descriptions accept JSON objects and arrays in addition
to strings. Descriptions may be `null`. Boolean true/false criteria are optional.
The SDK uses the neutral name `boolean` and maps it to TypeSafe's `noul` field.

### Rounded values and confidence

TypeSafe returns scores and probabilities rounded to two decimal places.
`result.rounding` reports this precision so the SDK can account for rounding when
checking distribution sums and weighted means. The returned values are preserved
unchanged; rounding means probabilities may not add up to exactly one.

Confidence is a separate TypeSafe statistic, available under
`result.providerMetadata.typesafe.confidence[questionId]` for Choice and Score
answers. Boolean probability always means P(true), not confidence in either
outcome. Choose decision thresholds in application code.

### Errors and retries

Provider failures use `APICallError`, including validation and authentication
errors. Core retries transient failures such as `429` and `529` according to
`maxRetries` (default: 2). `abortSignal`, request headers, and custom fetch are
forwarded. There is no provider-side retry loop.

No provider-specific options are currently defined. Unknown entries under
`providerOptions.typesafe` produce unsupported-option warnings. Language,
embedding, and image model factories throw `NoSuchModelError`.

Decision models support workflow serialization. A custom fetch function is not
serialized; restored models use the default fetch implementation.
