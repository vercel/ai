# Hume Provider

The [Hume](https://hume.ai/) provider is available in the `@ai-sdk/hume` package.
It supports the [Hume Audio Decisions API](https://dev.hume.ai/audio-decisions/docs/overview),
which answers Boolean, Choice, and Score questions about a recording with
estimates of how human raters would respond.
Hume retired its text-to-speech (TTS) API on November 13, 2026, so the package no longer includes a speech model.

## Setup

Install `ai` and `@ai-sdk/hume`:

<InstallPackages packages="ai @ai-sdk/hume" />

Create an API key on the [Hume Platform](https://cloud.hume.ai/settings/organization/api-keys) and set it in the `HUME_API_KEY` environment variable:

```bash
export HUME_API_KEY=your_api_key_here
```

## Provider Instance

Import the default instance:

```ts
import { hume } from '@ai-sdk/hume';
```

Or create a customized instance:

```ts
import { createHume } from '@ai-sdk/hume';

const hume = createHume({
  apiKey: process.env.HUME_API_KEY,
});
```

The following settings are optional:

- **apiKey** _string | PromiseLike&lt;string&gt; | (() =&gt; string | PromiseLike&lt;string&gt;)_: The key sent in the `X-Hume-Api-Key` header. Defaults to the `HUME_API_KEY` environment variable.

  Pass a function to resolve credentials before each request, including when keys
  rotate. The function can return a string or a promise. Credential caching and
  refresh are managed by the function.

- **baseURL** _string_: The API URL prefix. Defaults to `https://api.cloud.hume.ai`.
- **headers** _Record&lt;string, string&gt;_: Additional request headers.
- **fetch** _typeof fetch_: A custom fetch implementation.

## Decision Models

Use `hume.decisionModel()` with
[`experimental_decide`](/docs/reference/ai-sdk-core/decide) to call the
[Audio Decisions API](https://dev.hume.ai/audio-decisions/reference/decisions/create).
This API is experimental and may change in patch releases.

```ts
import { hume } from '@ai-sdk/hume';
import { experimental_decide as decide } from 'ai';
import { readFileSync } from 'node:fs';

const result = await decide({
  model: hume.decisionModel('audio-decisions'),
  state: [
    { type: 'text', text: 'A voice message left on the support line.' },
    {
      type: 'file',
      mediaType: 'audio/mpeg',
      data: readFileSync('voicemail.mp3'),
    },
  ],
  questions: {
    frustrated: {
      type: 'boolean',
      instructions: 'Does the caller sound frustrated?',
    },
    request: {
      type: 'choice',
      instructions: 'What is the caller asking for?',
      criteria: {
        refund: 'Money back for a purchase',
        support: 'Help with a problem',
        callback: 'A call back from the team',
      },
    },
    urgency: {
      type: 'score',
      instructions: 'How urgent does the caller sound?',
      criteria: ['Not urgent', 'Somewhat urgent', 'Very urgent'],
    },
  },
});

result.answers.frustrated.probability; // P(true), from 0 to 1
result.answers.request.choice; // 'refund' | 'support' | 'callback'
result.answers.urgency.score; // Expected zero-based level, from 0 to 2
```

`audio-decisions` is available. The provider maps SDK `boolean` questions to
Hume's native `noul` type and sends their `true` and `false` criteria when
present. Every question requires `instructions`, and criteria must be strings.
Hume rounds probabilities and scores to four decimal places. Box questions are
unsupported.

See Hume's guides to [writing questions](https://dev.hume.ai/audio-decisions/docs/writing-questions)
and [interpreting answers](https://dev.hume.ai/audio-decisions/docs/interpreting-answers)
for how to phrase questions and set thresholds.

### Audio and context

The state must contain exactly one MP3 (`audio/mpeg`) or WAV (`audio/wav`) file
part. An `audio/*` media type is resolved from the file's contents. Text parts
are joined with newlines and sent as Hume's `context`; JSON parts and other file
types are unsupported. Hume does not accept remote URLs, so pass file data
inline; `experimental_decide` downloads URL file state before calling the
provider when `experimental_download` is configured.

### Confidence, legends, and response metadata

Hume's confidence values and Score legends are available in
`providerMetadata.hume`, keyed by question ID. Confidence is distinct from the
selected option's probability.

```ts
const metadata = result.providerMetadata?.hume;
console.log(metadata?.confidence); // Choice and Score confidence by question ID
console.log(metadata?.legend); // Score index-to-description maps by question ID
console.log(result.response.id); // Hume run ID
console.log(result.usage.inputTokens);
```

### Decision limits

The provider validates these limits before sending the decision request:

| Input          | Limit                                            |
| -------------- | ------------------------------------------------ |
| Questions      | 1–20, each with `instructions`                   |
| Choice options | 2–20                                             |
| Score levels   | 2–10, all non-null                               |
| Audio          | Exactly one MP3 or WAV file; no other file types |

See Hume's [limits](https://dev.hume.ai/audio-decisions/docs/limits) for
API-enforced audio duration, request size, text length, and rate limits. Hume
decision models do not accept provider-specific options, `maxOutputTokens`, or
`reasoning`; these produce unsupported warnings and are not sent to the API.
