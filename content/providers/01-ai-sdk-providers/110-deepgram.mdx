# Deepgram Provider

The [Deepgram](https://deepgram.com/) provider contains language model support for the Deepgram transcription, speech generation, and Voice Agent APIs.
Deepgram models are not currently available through [AI Gateway](https://vercel.com/ai-gateway/models), so the opening example uses `@ai-sdk/deepgram` directly. See [Using AI Gateway](#using-ai-gateway) below for supported alternatives.

```ts
import { generateSpeech } from 'ai';
import { deepgram } from '@ai-sdk/deepgram';
import { writeFile } from 'node:fs/promises';

const { audio } = await generateSpeech({
  model: deepgram.speech('aura-2'),
  text: 'Hello, world!',
  outputFormat: 'mp3',
  voice: 'thalia',
  language: 'en',
});

await writeFile('speech.mp3', audio.uint8Array);
```

## Using `@ai-sdk/deepgram`

For direct access to Deepgram, install `ai` and `@ai-sdk/deepgram`:

## Provider Instance

You can import the default provider instance `deepgram` from `@ai-sdk/deepgram`:

```ts
import { deepgram } from '@ai-sdk/deepgram';
```

If you need a customized setup, you can import `createDeepgram` from `@ai-sdk/deepgram` and create a provider instance with your settings:

```ts
import { createDeepgram } from '@ai-sdk/deepgram';

const deepgram = createDeepgram({
  // custom settings, e.g.
  fetch: customFetch,
});
```

You can use the following optional settings to customize the Deepgram provider instance:

- **apiKey** _string | PromiseLike&lt;string&gt; | (() =&gt; string | PromiseLike&lt;string&gt;)_

  Pass a synchronous or asynchronous callback to resolve the key before each
  request. The callback is responsible for caching and refreshing credentials.

  API key that is being sent using the `Authorization` header.
  It defaults to the `DEEPGRAM_API_KEY` environment variable.

- **headers** _Record&lt;string,string&gt;_

  Custom headers to include in the requests.

- **fetch** _(input: RequestInfo, init?: RequestInit) => Promise&lt;Response&gt;_

  Custom [fetch](https://developer.mozilla.org/en-US/docs/Web/API/fetch) implementation.
  Defaults to the global `fetch` function.
  You can use it as a middleware to intercept requests,
  or to provide a custom fetch implementation for e.g. testing.

- **webSocket** _WebSocketConstructor_

  Custom WebSocket implementation for streaming transcription and streaming
  speech. Defaults to the global `WebSocket`. Use a header-capable implementation such as `ws` when you
  need to forward custom HTTP headers during the handshake.

## Speech Models

You can create models that call the [Deepgram text-to-speech API](https://developers.deepgram.com/docs/text-to-speech)
using the `.speech()` factory method.

The first argument is the voice family ID: `flux` ([Flux TTS](#flux-tts)),
`aura-2`, or `aura` (Aura-1). The voice and language are selected with the
`generateSpeech` `voice` and `language` options — the provider composes the
upstream Deepgram model ID as `<family>-<voice>-<language>` (language
defaults to `en`):

```ts
import { generateSpeech } from 'ai';
import { deepgram } from '@ai-sdk/deepgram';

const result = await generateSpeech({
  model: deepgram.speech('aura-2'),
  voice: 'thalia',
  language: 'en',
  text: 'Hello, world!',
});
```

<Note>
  Full voice model IDs (e.g. `deepgram.speech('aura-2-helena-en')`) still pass
  through, but the family ID + `voice`/`language` form above is the recommended
  path — it matches voice selection in the other speech providers.
</Note>

You can also pass additional provider-specific options using the `providerOptions` argument:

```ts highlight="7-11"
import { generateSpeech } from 'ai';
import { deepgram, type DeepgramSpeechModelOptions } from '@ai-sdk/deepgram';

const result = await generateSpeech({
  model: deepgram.speech('aura-2'),
  voice: 'helena',
  text: 'Hello, world!',
  providerOptions: {
    deepgram: {
      encoding: 'linear16',
      sampleRate: 24000,
    } satisfies DeepgramSpeechModelOptions,
  },
});
```

The following provider options are available:

- **encoding** _string_

  Encoding type for the audio output.
  Supported values: `'linear16'`, `'mulaw'`, `'alaw'`, `'mp3'`, `'opus'`, `'flac'`, `'aac'`.
  Optional.

- **container** _string_

  Container format for the output audio.
  Supported values: `'wav'`, `'ogg'`, `'none'`.
  Optional.

- **sampleRate** _number_

  Sample rate for the output audio in Hz.
  Supported values depend on the encoding: `8000`, `16000`, `24000`, `32000`, `48000`.
  Flux TTS also supports `44100` for `linear16`.
  Optional.

- **bitRate** _number | string_

  Bitrate of the audio in bits per second.
  For `mp3`: `32000` or `48000` (Flux TTS: `8000`, `16000`, `24000`, `32000`, `40000`, or `48000`).
  For `opus`: `4000` to `650000`.
  For `aac`: `4000` to `192000`.
  Optional.

- **expressivity** _number_

  Flux TTS only (beta). Delivery register from `-2` (calm) to `2` (animated);
  defaults to `0`, the voice's tuned delivery. Ignored with a warning for Aura
  models.
  Optional.

- **callback** _string_

  Not supported. Deepgram processes requests with a callback URL asynchronously
  and answers with a JSON acknowledgement (`{ "request_id": "..." }`) instead of
  audio, so `generateSpeech` rejects this option with an `InvalidArgumentError`.
  Call the Deepgram REST API directly when you need asynchronous callback
  delivery.

- **callbackMethod** _enum_

  Not supported. Only used together with `callback`, which `generateSpeech`
  rejects. Allowed values: `'POST'`, `'PUT'`. The option is ignored with an
  `unsupported` warning.

- **mipOptOut** _boolean_

  Opts out requests from the Deepgram Model Improvement Program.
  Optional.

- **tag** _string | array of strings_

  Label your requests for identification during usage reporting.
  Optional.

Speech results include Deepgram response details in
`providerMetadata.deepgram`: `modelName` (the resolved upstream model),
`modelUuid`, `additionalModelUuids`, `charCount` (the billed character
count), `breaksApplied`, `pronunciationsApplied`,
`pronunciationWarnings` (when present), and `requestId`.

The `generateSpeech` `speed` option is passed through to Deepgram's `speed`
parameter. Aura accepts speeds in the 0.7–1.5 range and Flux TTS 0.5–1.5 in
0.05 increments; Deepgram rejects other values with a 400 error, and speed is
not supported for all languages. `instructions` is not supported and is
ignored with a warning.

### Flux TTS

[Flux TTS](https://developers.deepgram.com/docs/flux-tts/overview) is
Deepgram's text-to-speech family for voice agents. Use the `flux` family ID
with a [Flux voice](https://developers.deepgram.com/docs/flux-tts/voices); the
`language` option selects the voice's language (English and 41 other
languages):

```ts
import { generateSpeech } from 'ai';
import { deepgram, type DeepgramSpeechModelOptions } from '@ai-sdk/deepgram';

const english = await generateSpeech({
  model: deepgram.speech('flux'),
  voice: 'haley',
  text: 'Hello, world!',
  providerOptions: {
    deepgram: { expressivity: 1 } satisfies DeepgramSpeechModelOptions,
  },
});

const spanish = await generateSpeech({
  model: deepgram.speech('flux'),
  voice: 'carmen',
  language: 'es',
  text: '¡Hola, mundo!',
});
```

Flux voices are served by Deepgram's `/v2/speak` endpoint and Aura voices by
`/v1/speak`; the provider picks the endpoint from the model ID. Full Flux
model IDs such as `deepgram.speech('flux-haley-en')` also pass through.

### Streaming Speech

Use `experimental_streamSpeech` with Flux TTS to synthesize text as it
arrives (for example from `streamText`) over Deepgram's
[`/v2/speak` WebSocket API](https://developers.deepgram.com/reference/text-to-speech/speak-flux):

```ts
import { deepgram } from '@ai-sdk/deepgram';
import { experimental_streamSpeech as streamSpeech } from 'ai';

const result = streamSpeech({
  model: deepgram.speech('flux'),
  voice: 'haley',
  text: textStream, // e.g. streamText(...).textStream
  outputFormat: { type: 'audio/pcm', rate: 24000 },
});

for await (const chunk of result.audioStream) {
  // raw 16-bit little-endian PCM
}

console.log(await result.usage);
```

The socket emits raw audio only: `audio/pcm` (16-bit little-endian at `8000`,
`16000`, `24000`, `32000`, `44100`, or `48000` Hz; default `24000`),
`audio/pcmu`, or `audio/pcma` (`8000` or `16000` Hz; default `8000`). Text
parts are forwarded as they arrive and can split anywhere; the end of the text
ends the turn. `speed`, `expressivity`, `mipOptOut`, and `tag` apply, while
the batch-only `encoding`, `container`, `sampleRate`, and `bitRate` options
are ignored with a warning. A stream speaks a single voice. `result.usage`
reports Deepgram's billable character count, and the connection is kept alive
while the text input is idle. Aura models do not support streaming speech.

## Transcription Models

You can create models that call the [Deepgram transcription API](https://developers.deepgram.com/docs/pre-recorded-audio)
using the `.transcription()` factory method.

The first argument is the model id e.g. `nova-3`.

```ts
const model = deepgram.transcription('nova-3');
```

You can also pass additional provider-specific options using the `providerOptions` argument. For example, supplying the `summarize` option will enable summaries for sections of content.

```ts highlight="11-15"
import { transcribe } from 'ai';
import {
  deepgram,
  type DeepgramTranscriptionModelOptions,
} from '@ai-sdk/deepgram';
import { readFile } from 'fs/promises';

const result = await transcribe({
  model: deepgram.transcription('nova-3'),
  audio: await readFile('audio.mp3'),
  providerOptions: {
    deepgram: {
      summarize: 'v2',
    } satisfies DeepgramTranscriptionModelOptions,
  },
});
```

The following provider options are available:

- **language** _string_

  Language code for the audio.
  Supports numerous ISO-639-1 and ISO-639-3 language codes.
  Optional.

- **detectLanguage** _boolean_

  Whether to enable automatic language detection.
  When true, Deepgram will detect the language of the audio.
  Optional.

- **smartFormat** _boolean_

  Whether to apply smart formatting to the transcription.
  Optional.

- **punctuate** _boolean_

  Whether to add punctuation to the transcription.
  Optional.

- **summarize** _enum | boolean_

  Whether to generate a summary of the transcription.
  Allowed values: `'v2'`, `false`.
  Optional.

- **topics** _boolean_

  Whether to detect topics in the transcription.
  Optional.

- **detectEntities** _boolean_

  Whether to detect entities in the transcription.
  Optional.

- **redact** _string | array of strings_

  Specifies what content to redact from the transcription.
  Optional.

- **search** _string_

  Search term to find in the transcription.
  Optional.

- **diarize** _boolean_

  Whether to identify different speakers in the transcription.
  Defaults to `false`. Note that Deepgram bills speaker diarization as a
  per-minute add-on.
  Optional.

- **utterances** _boolean_

  Whether to segment the transcription into utterances.
  Optional.

- **uttSplit** _number_

  Threshold for splitting utterances.
  Optional.

- **fillerWords** _boolean_

  Whether to include filler words (um, uh, etc.) in the transcription.
  Optional.

- **paragraphs** _boolean_

  Whether to format the transcription into paragraphs.
  Optional.

- **intents** _boolean_

  Whether to detect intents in the transcription.
  Optional.

- **sentiment** _boolean_

  Whether to analyze sentiment in the transcription.
  Optional.

- **keyterm** _string_

  Key term to improve recognition accuracy for.
  Optional.

- **replace** _string_

  String to replace redacted content with.
  Optional.

## Streaming Transcription

Use `experimental_streamTranscribe` with Nova models to transcribe live audio
through Deepgram's [`/v1/listen` WebSocket API](https://developers.deepgram.com/reference/speech-to-text/listen-streaming):

```ts
import { deepgram } from '@ai-sdk/deepgram';
import { experimental_streamTranscribe as streamTranscribe } from 'ai';

const result = streamTranscribe({
  model: deepgram.transcription('nova-3'),
  audio: audioStream, // ReadableStream<Uint8Array | string>
  inputAudioFormat: { type: 'audio/pcm', rate: 16000 },
  providerOptions: {
    deepgram: {
      language: 'en',
      streaming: { interimResults: true, endpointing: 300 },
    },
  },
});

for await (const part of result.fullStream) {
  if (part.type === 'transcript-partial' || part.type === 'transcript-final') {
    console.log(part.type, part.text);
  }
}

console.log(await result.text);
console.log(await result.segments);
console.log(await result.durationInSeconds);
```

Input chunks contain raw 16-bit little-endian PCM (`audio/pcm`), G.711 μ-law
(`audio/pcmu`), or G.711 A-law (`audio/pcma`). Set `rate` to the actual sample
rate. Strings contain base64-encoded audio. Closing the audio input flushes the
remaining transcript before the result finishes. Idle input connections send
keepalive messages, and cancellation closes the socket and cancels the audio
source.

The provider authenticates with WebSocket subprotocols when using a Deepgram API
key, so native WebSockets work without custom headers. Keep long-lived API keys
on the server. Flux models use the turn-based `/v2/listen` protocol; see
[Flux Streaming Transcription](#flux-streaming-transcription).

To authenticate with a short-lived token, use the Bearer scheme:

```ts
const deepgram = createDeepgram({
  apiKey: temporaryToken,
  headers: { authorization: `Bearer ${temporaryToken}` },
});
```

Live transcription supports `language`, `smartFormat`, `punctuate`, `diarize`,
`fillerWords`, `redact`, `replace`, `search`, and `keyterm`. Batch-only settings
produce warnings. The optional `providerOptions.deepgram.streaming` object
accepts:

- **interimResults** _boolean_: emit revisable partial transcripts (default `false`).
- **endpointing** _number | false_: silence duration in milliseconds before
  finalizing an utterance; `false` disables endpointing.
- **channels** _number_: number of interleaved audio channels (default `1`).
- **multichannel** _boolean_: transcribe each channel independently.
- **vadEvents** _boolean_: include speech-start events when `includeRawChunks` is enabled.
- **utteranceEndMs** _number_: silence duration in milliseconds before an
  utterance-end event; at least `1000`, used with `interimResults`.

Final transcript parts contain channel indices and timing. Aggregate text and
segments combine all channels in chronological order; consume `fullStream` when
you need each segment's channel index. Word timings appear in `result.segments`, and Deepgram's reported duration appears in
`result.durationInSeconds`. Native usage (`{ seconds: duration }`) is forwarded
to the `experimental_onStreamTranscriptionEnd` telemetry callback. The
`providerMetadata.deepgram.speechFinal` flag indicates an utterance boundary.
Enable `includeRawChunks` for complete provider events, including request IDs,
speaker labels, and utterance-end events.

### Flux Streaming Transcription

[Flux](https://developers.deepgram.com/docs/flux/quickstart) models
(`flux-general-en` and the multilingual `flux-general-multi`) are
conversational, streaming-only models with built-in end-of-turn detection,
served by Deepgram's
[`/v2/listen` WebSocket API](https://developers.deepgram.com/reference/speech-to-text/listen-flux):

```ts
import { deepgram } from '@ai-sdk/deepgram';
import { experimental_streamTranscribe as streamTranscribe } from 'ai';

const result = streamTranscribe({
  model: deepgram.transcription('flux-general-multi'),
  audio: audioStream, // ReadableStream<Uint8Array | string>
  inputAudioFormat: { type: 'audio/pcm', rate: 16000 },
  providerOptions: {
    deepgram: {
      streaming: { languageHints: ['en', 'es'], eotThreshold: 0.7 },
    },
  },
});

for await (const part of result.fullStream) {
  if (part.type === 'transcript-final') {
    console.log(part.text, part.providerMetadata?.deepgram);
  }
}
```

Every Flux turn event becomes a transcript part with the transcript of the
current turn: `EndOfTurn` events are `transcript-final` parts, and all other
events (`StartOfTurn`, `Update`, `EagerEndOfTurn`, `TurnResumed`) are
`transcript-partial` parts. `providerMetadata.deepgram` contains the `event`,
the `turnIndex`, the `endOfTurnConfidence`, the `trigger` of a turn end, and
the detected `languages` (Flux Multilingual). Closing the audio input does
not end the active turn, so its latest transcript is emitted as a final part
before the result finishes. Deepgram recommends sending audio in 80ms chunks.

Flux supports the `keyterm` and `redact` (`numbers`, `aggressive_numbers`)
options and these `providerOptions.deepgram.streaming` options:

- **eotThreshold** _number_: confidence required to end a turn, `0.5` to `1`
  (default `0.7`).
- **eagerEotThreshold** _number_: confidence required for an early
  `EagerEndOfTurn` event, `0.3` to `0.9`; enables `EagerEndOfTurn` and
  `TurnResumed` events.
- **eotTimeoutMs** _number_: silence in milliseconds that forces the end of a
  turn, `500` to `60000` (default `5000`).
- **languageHints** _string[]_: language codes that bias
  `flux-general-multi`; without hints the language is detected
  automatically. A single `language` option is used as one hint.

The Nova streaming options above are ignored with a warning for Flux models,
and the Flux options for Nova models. Flux does not report an audio duration
or usage, so `result.durationInSeconds` is the duration of the audio that was
sent. Flux models cannot be used with `transcribe`.

## Realtime Voice Agent

<Note type="warning">Realtime is an experimental feature.</Note>

`deepgram.experimental_realtime()` connects to Deepgram's
[Voice Agent API](https://developers.deepgram.com/docs/voice-agent): a single
WebSocket that takes audio in and returns audio out, with Deepgram running
speech-to-text, an LLM, and text-to-speech in between.

```ts
import { deepgram } from '@ai-sdk/deepgram';

const model = deepgram.experimental_realtime('voice-agent');
```

The model ID is `voice-agent`. What runs inside the agent is chosen per
session: the LLM with the `think` provider option, the voice with `voice`, and
the speech-to-text model with `inputAudioTranscription.model`. Listening and
speaking default to Flux.

### Server-Owned Connections

The model works where your code owns the WebSocket, as described in
[Server-owned connections](/docs/ai-sdk-core/realtime#server-owned-connections).
The agent sends its audio as binary frames. Pass those frames to the parser as
received, and pass text frames as parsed JSON:

```ts
import { deepgram } from '@ai-sdk/deepgram';
import type { Experimental_RealtimeClientEvent as RealtimeClientEvent } from 'ai';
import { WebSocket } from 'ws';

const model = deepgram.experimental_realtime('voice-agent');
const { url, headers, protocols } = await model.getServerWebSocketConfig();
const socket = new WebSocket(url, protocols, { headers });
const parse = model.createServerEventParser();

async function send(event: RealtimeClientEvent) {
  const data = await model.serializeClientEvent(event);
  if (data == null) return; // the agent has no message for this event
  // Audio is sent as a binary frame, everything else as JSON.
  socket.send(data instanceof Uint8Array ? data : JSON.stringify(data));
}

socket.on('message', (data, isBinary) => {
  const events = parse(isBinary ? data : JSON.parse(data.toString()));

  for (const event of Array.isArray(events) ? events : [events]) {
    if (event.type === 'session-created') {
      void send({
        type: 'session-update',
        config: { instructions: 'You are a helpful voice assistant.' },
      });
    } else if (event.type === 'session-updated') {
      // start sending microphone audio with `input-audio-append` events
    } else if (event.type === 'audio-delta') {
      // play the base64-encoded audio in `event.delta`
    }
  }
});
```

The parser keeps track of the agent's current turn. Create one parser per
connection with `createServerEventParser()` and give it the frames in the
order they arrive. The returned headers contain your API key, so keep the
connection settings on your server. A complete Node.js example is in
[`basic.ts`](https://github.com/vercel/ai/blob/main/examples/ai-functions/src/realtime/deepgram/basic.ts).

Send audio continuously, including silence, as an open microphone would; the
provider does not send keep-alive messages. Deepgram ends a connection that
receives no client message for about 60 seconds, reporting an `error` event
with the code `CLIENT_MESSAGE_TIMEOUT`.

<Note>
  The browser `experimental_useRealtime` hook cannot drive this model yet. It
  reads every incoming frame as JSON, and the agent's audio arrives as binary
  frames. This also applies when the hook connects through a relay that forwards
  frames unchanged.
</Note>

### Session Configuration

The first `session-update` event configures the agent:

```ts
import type { DeepgramRealtimeModelOptions } from '@ai-sdk/deepgram';

await send({
  type: 'session-update',
  config: {
    instructions: 'You are a helpful voice assistant. Respond briefly.',
    voice: 'flux-alexis-en',
    inputAudioFormat: { type: 'audio/pcm', rate: 24000 },
    outputAudioFormat: { type: 'audio/pcm', rate: 24000 },
    tools: [
      {
        type: 'function',
        name: 'get_weather',
        description: 'Get the current weather for a city',
        parameters: {
          type: 'object',
          properties: { city: { type: 'string' } },
          required: ['city'],
        },
      },
    ],
    providerOptions: {
      deepgram: {
        think: { provider: 'open_ai', model: 'gpt-4o-mini' },
        greeting: 'Hello! How can I help?',
      } satisfies DeepgramRealtimeModelOptions,
    },
  },
});
```

- **instructions** _string_: the system prompt for the LLM.
- **voice** _string_: a full Deepgram voice model ID, such as the Flux voice
  `flux-alexis-en` or the Aura voice `aura-2-thalia-en`. Deepgram uses its
  default voice when it is omitted.
- **tools**: functions the agent can call. A call arrives as a
  `function-call-arguments-done` event. Return the result with a
  `conversation-item-create` event that contains a `function-call-output`
  item with the event's `callId` and the function `name`; the agent then
  speaks its answer.
- **inputAudioFormat**, **outputAudioFormat**: `audio/pcm` (16-bit
  little-endian, default `24000` Hz), `audio/pcmu`, or `audio/pcma` (default
  `8000` Hz). Output audio is raw, without a container.
- **inputAudioTranscription.model** _string_: the speech-to-text model.
  Defaults to `flux-general-en`. `inputAudioTranscription.language` is passed
  as a language hint to `flux-general-multi` and as the language to non-Flux
  models such as `nova-3`.
- **turnDetection**: Flux decides when a turn ends with a model instead of a
  silence timer. `silenceDurationMs` sets the silence that ends a turn
  regardless of the model's confidence (limited to `500` to `60000` ms);
  `threshold` and `prefixPaddingMs` are ignored. Set `turnDetection` to `null`
  or `{ type: 'disabled' }` to suppress automatic end-of-turn detection, and
  send an `input-audio-commit` event when the user's turn is complete. Both
  need a Flux speech-to-text model: disabling turn detection with another
  model throws an error, and for an `input-audio-commit` event Deepgram then
  only sends a warning and the turn does not end.

The following `providerOptions.deepgram` options are available:

- **think** _object_

  The LLM the agent thinks with: `provider` is a Deepgram think provider type
  and `model` one of its model IDs, for example
  `{ provider: 'anthropic', model: 'claude-haiku-4-5' }`. See Deepgram's
  [supported LLMs](https://developers.deepgram.com/docs/voice-agent-llm-models).
  Defaults to `{ provider: 'open_ai', model: 'gpt-4o-mini' }`.

- **greeting** _string_

  A message the agent speaks when the session starts.

- **eotThreshold** _number_

  Flux end-of-turn confidence required before the agent replies, `0.5` to `1`
  (default `0.7`). Higher values wait longer before treating a pause as the
  end of the user's turn.

Deepgram accepts the session configuration once per connection. Later
`session-update` events can change the `voice` or add to the `instructions`
(Deepgram appends the text to the current prompt), one of them per event.
Updates to any other setting throw an error; open a new connection instead.
If Deepgram rejects an update, such as an unknown voice, it reports an `error`
event and closes the connection.

### Events

The agent's turn is reported as one response:

- `session-created` when the connection opens, and `session-updated` when the
  configuration or an update has been applied.
- `speech-started` when the user starts speaking, and
  `input-transcription-completed` with the transcript of the user's turn.
- `response-created`, then `audio-delta` events with the agent's audio and
  `audio-transcript-delta` events with its text, one sentence at a time.
- `audio-done`, `audio-transcript-done`, and `response-done` when the agent
  has finished. If the user interrupts, the response ends with the status
  `cancelled`.
- `error` for Deepgram errors. Deepgram usually closes the connection after
  an error.

All other agent messages, including warnings, are passed through as `custom`
events with the Deepgram message type in `rawType`. Deepgram reports problems
with the agent's speech as warnings, so a response with the status `completed`
does not guarantee that the audio matched the text. Watch for `custom` events
with `rawType: 'Warning'`.

A `conversation-item-create` event with a text message is handled as if the
user had spoken the text. Deepgram reports it back as a user transcript, so
it also arrives as an `input-transcription-completed` event, preceded by a
`speech-started` event.

### Short-Lived Tokens

`deepgram.experimental_realtime.getToken()` requests a
[temporary token](https://developers.deepgram.com/docs/token-based-authentication)
from Deepgram for clients that open the agent WebSocket themselves:

```ts
const secret = await deepgram.experimental_realtime.getToken({
  model: 'voice-agent',
  expiresAfterSeconds: 60,
});
```

`expiresAfterSeconds` can be `1` to `3600`; Deepgram applies its own default
when it is omitted. Your Deepgram API key needs permission to create tokens,
otherwise Deepgram rejects the request. Pass `secret.token` and `secret.url`
to `model.getWebSocketConfig()` to get the WebSocket URL and the subprotocols
that carry the token. The client has to handle the agent's binary audio
frames as shown above.

### Unsupported Features

- Browser sessions with `experimental_useRealtime`.
- Text-only output: the agent always speaks, and `outputModalities` without
  `audio` throws an error.
- `response-create`, `response-cancel`, `input-audio-clear`,
  `conversation-item-truncate`, and complete audio messages. The agent
  replies on its own after each user turn, function result, or text message,
  so these events are ignored.
- Changing the LLM, tools, audio formats, or turn detection during a session.
- Usage information: no usage is reported for agent sessions.
- Other Voice Agent settings, such as third-party speech providers, functions
  that Deepgram calls itself, and conversation history.
