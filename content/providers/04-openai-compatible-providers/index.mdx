# OpenAI Compatible Providers

You can use the [OpenAI Compatible Provider](https://www.npmjs.com/package/@ai-sdk/openai-compatible) package to use language model providers that implement the OpenAI API.

Below we focus on the general setup and provider instance creation. You can also [write a custom provider package leveraging the OpenAI Compatible package](/providers/openai-compatible-providers/custom-providers).

We provide detailed documentation for the following OpenAI compatible providers:

- [LM Studio](/providers/openai-compatible-providers/lmstudio)
- [NIM](/providers/openai-compatible-providers/nim)
- [ModelRush](/providers/openai-compatible-providers/modelrush)
- [Cheaper Inference](/providers/openai-compatible-providers/cheaper-inference)
- [Heroku](/providers/openai-compatible-providers/heroku)
- [Clarifai](/providers/openai-compatible-providers/clarifai)
- [NEAR AI Cloud](/providers/openai-compatible-providers/nearai)
- [TopxAI](/providers/openai-compatible-providers/topxai)
- [Synthorai](/providers/openai-compatible-providers/synthorai)
- [Meta (Muse)](/providers/openai-compatible-providers/meta)
- [Morse](/providers/openai-compatible-providers/morse)

The general setup and provider instance creation is the same for all of these providers.

## Setup

The OpenAI Compatible provider is available via the `@ai-sdk/openai-compatible` module. You can install it with:

<InstallPackages packages="@ai-sdk/openai-compatible" />

## Provider Instance

To set up an OpenAI compatible provider, you can use the `createOpenAICompatible` function from `@ai-sdk/openai-compatible`.
To use it, you need to provide:

- **name** - the name of the provider, used in logging and error messages.
- **apiKey** (optional) - the API key for the provider.
- **baseURL** - the base URL for the provider's API, without `/chat/completions` suffix.
- **headers** (optional) - additional headers for requests.

```ts
import { createOpenAICompatible } from '@ai-sdk/openai-compatible';

const provider = createOpenAICompatible({
  name: 'provider-name',
  headers: {
    Authorization: `Bearer ${process.env.MY_API_KEY}`,
  },
  baseURL: 'https://api.example.com/v1',
});
```

## Language Models

You can create language models using the `.languageModel()` or `.chatModel()` factory methods on the provider instance:

```ts
const model = provider.languageModel('model-name');
const model = provider.chatModel('model-name');
```

You can then pass the model to AI SDK functions:

```ts
import { generateText } from 'ai';

const { text } = await generateText({
  model: provider.chatModel('model-name'),
  prompt: 'Hello!',
});
```

## Completion Models

You can create completion models using the `.completionModel()` factory method on the provider instance:

```ts
const model = provider.completionModel('model-name');
```

## Embedding Models

You can create embedding models using the `.textEmbeddingModel()` or `.embedding()` factory methods on the provider instance:

```ts
const embeddingModel = provider.textEmbeddingModel('model-name');
const embeddingModel = provider.embedding('model-name');
```

You can then pass the model to `ai` functions like `embed` and `embedMany`.

## Image Models

You can create image models using the `.imageModel()` or `.image()` factory methods on the provider instance:

```ts
const imageModel = provider.imageModel('model-name');
const imageModel = provider.image('model-name');
```

You can then pass the model to `ai` functions like `generateImage`.

## Speech Models (Text-to-Speech)

You can create speech models using the `.speechModel()` or `.speech()` factory methods on the provider instance:

```ts
const speechModel = provider.speechModel('model-name');
const speechModel = provider.speech('model-name');
```

You can then pass the model to `ai` functions like `generateSpeech`.

## Transcription Models (Speech-to-Text)

You can create transcription models using the `.transcriptionModel()` or `.transcription()` factory methods on the provider instance:

```ts
const transcriptionModel = provider.transcriptionModel('model-name');
const transcriptionModel = provider.transcription('model-name');
```

You can then pass the model to `ai` functions like `transcribe`.

## Provider-Specific Options

To pass additional settings to the provider, use the `providerOptions` parameter. The key for provider-specific options should match the `name` you specified in `createOpenAICompatible`.

```ts
import { generateText } from 'ai';

const provider = createOpenAICompatible({
  name: 'my-provider',
  baseURL: 'https://api.example.com/v1',
});

const { text } = await generateText({
  model: provider.chatModel('model-name'),
  prompt: 'Hello!',
  providerOptions: {
    'my-provider': { customParam: 'value' },
  },
});
```

## Common Issues

Some provider's API's are not fully OpenAI compatible. Here are some common issues and how to fix them:

### Streaming Issues

Some providers send additional data in the streaming response. You can filter these out by providing a custom `fetch` and `ResponseTransformStream`.

See the LM Studio provider for an [example](https://github.com/vercel/ai/blob/main/packages/lmstudio/src/lmstudio-provider.ts).

### Response Schema Issues

Some providers send responses that do not conform to the OpenAI schema, e.g. missing token usage information. When this happens, the validation of the response body will fail.

You can relax the schema validation by setting the `strict` option to `warn` on the provider:

```ts
const provider = createOpenAICompatible({
  name: 'provider-name',
  apiKey: process.env.MY_API_KEY,
  baseURL: 'https://api.example.com/v1',
  options: {
    strict: 'warn',
  },
});
```

This will accept all response bodies and warn you if the response does not conform to the expected schema.
